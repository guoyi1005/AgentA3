### 2.4 账号异常时如何恢复

在服务器 MySQL 中重新导入测试账号（可重复执行）：

```bash
# 角色
mysql -uroot -p"$MYSQL_ROOT_PASSWORD" smart-campus < AppBackend/01_roles.sql
# 四角色标准测试号
mysql -uroot -p"$MYSQL_ROOT_PASSWORD" smart-campus < AppBackend/02_test_users.sql
```

若需试卷联调样例数据（绑定 `zzs`）：

```bash
mysql -uroot -p"$MYSQL_ROOT_PASSWORD" smart-campus < deploy/seed-paper-test-data.sql
```

> 注意：提交 Compose 默认 `SPRING_SQL_INIT_MODE=never`，**不会**自动执行可能清空业务表的 `data.sql`。演示数据请用上述非破坏性脚本或已审核备份导入。

## 5. 服务器一键部署（从零复现）

完整技术细节见：`docs/deployment/submission-runbook.md`、`AppBackend/deploy/README.md`。

### 5.1 前置

- Docker Engine 24+、Compose v2  
- 开放或映射端口：`3000`（Web）；后端/AI 建议仅本机或内网

### 5.2 配置

```bash
cp deploy/.env.example deploy/.env
# 必填：MYSQL_ROOT_PASSWORD、JWT_SECRET、AI_INTERNAL_TOKEN（禁止 CHANGE_ME）
# 建议：PUBLIC_BASE_URL=http://129.211.82.112:3000
```

### 5.3 启动与验收

```bash
docker compose --env-file deploy/.env -f deploy/compose.submission.yml up -d --build
docker compose --env-file deploy/.env -f deploy/compose.submission.yml ps
bash deploy/verify.sh
```

`verify.sh` 检查：

- Java `/actuator/health`、`/actuator/readiness`
- Python `/healthz`
- Web `http://localhost:3000`
- 未登录访问 `/api/auth/current-user` 应返回 401

服务器脚本：

```bash
chmod +x AppBackend/deploy/deploy-on-server.sh deploy/verify.sh
./AppBackend/deploy/deploy-on-server.sh
```

### 5.4 服务拓扑（五服务）

```
浏览器 / APP
    │
    ▼
AppWeb :3000 (Nginx) ──/api──► Java backend
                                │
                                ├── MySQL
                                ├── Redis
                                └── Python AI Server（内部令牌）
```

外部依赖（不随镜像内置）：MaxKB、模型提供商、讯飞 ASR —— 需在管理端配置后才可演示对应能力。

## 7. 常见问题

| 现象 | 处理 |
|---|---|
| Web 能开，登录失败 | 确认账号角色与入口匹配；密码是否为 `admin123`；数据库是否已导入用户 |
| 小程序请求失败 | 检查 `VITE_API_BASE_URL` 是否指向 `http://129.211.82.112:3000`；域名/IP 是否在合法请求列表 |
| AI 无回复 / 智能体不可用 | 打开智能体设置检查工具开关与模型绑定；确认 Python AI 容器健康 |
| `/api` 502 | 查看 Java 容器日志与 Compose 网络别名 |
| 会议转写失败 | 语音模型/讯飞凭据未配置或网络不通（属外部依赖） |
